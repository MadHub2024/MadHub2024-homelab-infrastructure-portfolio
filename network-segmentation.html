Case study 01

Multi-VLAN Network Segmentation

Designing a secure Omada network that isolates device classes while maintaining the services each group legitimately needs.

OmadaVLANsACLsmDNSRouting

Challenge

The environment included servers, workstations, IoT devices, media devices, printers, guests, and management equipment. A flat network would create unnecessary trust and a larger attack surface.

Design

I created dedicated network segments for management, servers, workstations, IoT, media, printers, and guests. Inter-VLAN access is denied by default and allowed only where a documented service dependency exists.

Management VLAN  → network infrastructure
Server VLAN      → Linux and Docker services
Workstation VLAN → trusted user endpoints
IoT VLAN         → constrained smart devices
Media VLAN       → TVs and streaming devices
Printer VLAN     → restricted printing services
Guest VLAN       → internet-only access

Implementation approach

  • Created explicit DNS rules to the internal resolver.
  • Allowed narrowly scoped access to Hubitat, Home Assistant, and printing services.
  • Used mDNS/Bonjour bridging only where discovery was required.
  • Maintained a default-deny inter-VLAN posture.

Operational lessons

Segmentation is not complete when VLANs exist; it becomes useful when dependencies are mapped, ACL behavior is tested from the client side, and exceptions are documented. Service discovery protocols require special attention because broadcast traffic does not naturally cross VLAN boundaries.

Result

The final design limits lateral movement, reduces unnecessary trust, and preserves required user experiences such as AirPrint, automation, DNS, and remote administration.
