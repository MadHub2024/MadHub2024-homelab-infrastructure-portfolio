Multi-VLAN Network Segmentation

Designed a secure TP-Link Omada network that isolates device classes (management, servers, workstations, IoT, media, printers, guests) while maintaining necessary service dependencies.

TP-Link Omada VLANs ACLs mDNS Routing
Outcome: Least-privilege network isolation with zero-trust inter-VLAN policies while preserving DNS resolution, AirPrint, automation, and remote administration workflows.

Key Achievement: Reduced attack surface by segmenting 7+ device classes with explicit allow-lists, mapped all service dependencies, and validated ACL behavior from client-side testing.

02

Layered DNS Architecture

Built a multi-layer DNS infrastructure using Technitium DNS (authoritative internal zones) and AdGuard Home (filtering, encrypted upstream) to provide reliable, fast, and secure name resolution across all VLANs.

Technitium DNS AdGuard Home Split DNS DoH Troubleshooting
Outcome: Centralized naming authority, network-wide content filtering, and encrypted upstream resolution without exposing private applications to public DNS.

Key Achievement: Designed internal zones (.home, .dbservices, internal view of dbservicessolutions.org) with clear fault boundaries and documented troubleshooting procedures using dig, nslookup, and authoritative zone inspection.

Why These Case Studies?

Each case study represents a major architectural or operational challenge in my homelab. Rather than simply listing technologies, I document:

  • The Challenge: What problem needed to be solved?
  • Design Decisions: Why did I choose this approach?
  • Implementation Details: How was it deployed and configured?
  • Lessons Learned: What went wrong, and how did I fix it?
  • Measurable Results: How does this improve reliability, security, or observability?
